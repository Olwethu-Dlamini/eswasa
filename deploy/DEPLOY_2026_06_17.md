`patch_standards_routing_2026_06_17.sql` — three fixes:

  removed `#technical-committees` anchor to `tcp.php`.
- Fixes FAQ #19's answer text, which linked to the same removed anchor.

  → `≤ 30 days`, `Ôëñ 60 days` → `≤ 60 days`).

`patch_fix_mojibake_2026_06_17.sql` — **site-wide character repair (63 rows).**
The 2026-05-25 mysqldump was taken with the Windows CP850 console codepage, so
every special character in `page_content` was mangled: em dashes (`—`) became
`ÔÇö`, `≤` became `Ôëñ`, `½`/`·` became `┬¢`/`┬À`, etc. This shows as garbled
"words" on most pages (About values, Certification/Ingelo/Management-Systems
descriptions, Standards body text, Training durations…). The patch sets each
affected key to its correct value. Run it once against production.

> Root cause is the dump's encoding, not the app — the live connection is
> `utf8mb4` and the PHP defaults are correct UTF-8. `migration_2026_05_25.sql`
> still carries the mojibake for these rows (historical artifact); run this
> repair patch after it on any fresh import.

Quick check after running:
```sql
SELECT page_key, content FROM page_content WHERE page_key = 'std_cta_btn_2_url';
-- expect: tcp.php
-- And confirm no mojibake remains (should return 0):
SELECT COUNT(*) FROM page_content WHERE content LIKE BINARY CONCAT('%', 0xC394, '%');
```
