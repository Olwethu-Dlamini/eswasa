## 2. Run the SQL migration

Apply `deploy/migration_2026_05_26.sql` to the production database.

- **phpMyAdmin** → Import tab → choose the file.
- **Shell**: `mysql -u <user> -p <db> < migration_2026_05_26.sql`

Safe to re-run — every statement is idempotent
(`CREATE TABLE IF NOT EXISTS`, `INSERT … WHERE NOT EXISTS`, and a
guarded `ADD COLUMN` block).

What it does:

1. Creates `eswasa_work_programmes` and wipes the legacy
   `work_item_[1-5]_*` rows from `page_content`.
2. Creates `eswasa_policies` and seeds the 12 historical entries (only
   if the table is empty).
3. Creates `eswasa_customer_feedback` with the `is_read` column. If a
   prior deploy of `customer-feedback.php` already lazy-created the
   table without `is_read`, the migration patches that in via a
   guarded procedure.

The verification SELECT at the bottom prints four counts — use those
to sanity-check the run.

`eswasa_event_images` is created lazily by
`includes/event_images.php` on first request, so it's not in the
migration.
