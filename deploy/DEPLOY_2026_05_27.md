## 2. Run the SQL migration

Apply `deploy/migration_2026_05_27.sql` to the production database.

- **phpMyAdmin** → Import tab → choose the file.
- **Shell**: `mysql -u <user> -p <db> < migration_2026_05_27.sql`

Safe to re-run — all destructive parts are idempotent
(`DELETE … WHERE title IN (…)`, `CREATE TABLE IF NOT EXISTS`,
`INSERT IGNORE` on explicit IDs).

What it does:

**Section 1 — `eswasa_policies` trim (same as before)**

Deletes 7 rows from `eswasa_policies`:
- Appeals Handling Procedure
- Rules for Use of the Certification Mark
- Grant of Certification Procedure
- Suspension, Withdrawal & Reduction of Scope
- Extending Scope of Certification
- Management Systems Certification Audits
- Special Audits Procedure

Rows are matched by `title` (stable across environments) rather than
`id`, since dev and prod auto-increment values diverge.

**Section 2 — new training tables**

Creates `training_sessions` (13 columns inc. code/family/title/sort_order/is_active)
and `training_intakes` (FK to sessions, start/end dates, label). Seeds them
with the 13 existing trainings and 28 intakes that used to live as
hard-coded PHP in `training-calendar.php`. The public page is unchanged
visually on day-zero — same trainings, same intake dates, same family
colours — but now everything is editable from the admin.

**Section 3 — new certified_organisations table**

Creates `certified_organisations` (name, standard, logo_path, sort_order,
is_active, timestamps). Seeds the 6 organisations currently shown on
`managementsystems.php` with their existing logo paths from
`assets/img/clients/`. Replaces the hard-coded `$clients` array on the
public page so the admin can manage the list.

**You also need to create an uploads directory:**

```
admin/uploads/orgs/
```

This is where new logo uploads land. It auto-creates on first upload if
the parent is writable, but pre-creating it (with the same permissions as
`admin/uploads/`) avoids any surprise.

The verification `SELECT`s at the bottom print:
- the 5 remaining policies,
- the row counts for the two training tables (should be 13 and 28), and
- the 6 seeded organisations (id, sort_order, name, standard, logo).

### The 7 PDFs themselves are NOT removed

The migration drops the DB rows only. The seven PDF files
(`CER_PR_002 PROCEDURE FOR APPEALS HANDLING.pdf`,
`CER_RU_028 RULES FOR THE USE OF THE CERTIFICATION MARK.pdf`,
`CER_PR_014 GRANT OF CERTIFICATION PROCEDURE.pdf`,
`CER_PR_026 PROCEDURE FOR SUSPENSION WITHDRAWAL REDUCED SCOPE OF CERTIFICATION.pdf`,
`CER_PR_012 EXTENDING SCOPE OF CERTIFICATION PROCEDURE.pdf`,
`CER_PR_020 PROCEDURE FOR MANAGEMENT SYSTEMS CERTIFICATION AUDITS.pdf`,
`CER_PR_028 SPECIAL AUDITS PROCEDURE.pdf`)
remain at the prod web root. Confirm nothing else links to them, then
optionally delete them manually via cPanel / SFTP.

## 3. Smoke test after deploy

### Critical regression check (the reason this round exists)
- **events.php** — list of events renders **below the header**, not
  just the header navbar. If only the header appears and the body is
  blank, the `db_connect.php` fix didn't land — re-verify the deployed
  file.
- **event-details.php?id=…** — detail page renders with title, body,
  and gallery.

### Header & footer socials
- **Top bar (every page)** — three items: `Certification` →
  `Certification.php`, `Standards` → `Standards.php`, then three
  social icons. The Facebook icon (first of the three) opens
  `https://www.facebook.com/eswasaupdates` in a new tab. LinkedIn and
  WhatsApp still href="#" — that's intentional until those URLs land.
- **Footer (every page)** — Facebook icon opens the same eswasaupdates
  URL in a new tab.
- View source — no nested `<ul>` inside `tg-header__top-social`; it's
  a single flat list.

### Content
- **training-about.php** → banking details section now shows
  `SWIFT Code: SBICSZMX`.
- **policies.php** — exactly 5 policies render, in this order:
  1. Impartiality Policy
  2. Complaints Handling Procedure
  3. Handling Requests for Information
  4. Privacy Policy
  5. Terms & Conditions
- **Anywhere `assets/img/steps-to-certification.jpg` is shown** — the
  new image appears (the previous one was ~157 KB; the new one is
  ~146 KB and visually different).

### Admin
- `admin/login.php` → `Policies` → Documents — the same 5 entries
  appear and editing still works.
- Any page whose images reference the new `admin/uploads/*` files
  (e.g. the page in admin where the breadcrumb / product images were
  last edited) — the images render correctly.

### Ingelo banner — single source of truth
- `ingelo.php` — breadcrumb banner shows whatever was last uploaded in
  `admin/login.php → Breadcrumb Images → Ingelo`.
- Admin → `Edit Ingelo Certification Page` → the Hero / Breadcrumb card
  no longer has a "Hero Background Image" upload — it shows a one-line
  note pointing to the Breadcrumb Images section. (The orphan
  `ingelo_img_hero` row in `page_content` is harmless; nothing reads
  it anymore.)

### Certified Organisations — fully admin-managed
- Public `managementsystems.php` → "Some of the Certified Organisations"
  section renders the **same 6 tiles** as before (GALP Eswatini,
  Eswatini Wire, ASD Medicals, Phocweni Clinic, MP Foods, Eagles Nest),
  in the same order, with the same logos / wordmark fallback. Source
  is now the `certified_organisations` table, not the hard-coded PHP
  array.
- Admin → `Management Systems Certification` → page is now **tabbed**:
  - **Certified Organisations tab** — list of 6 orgs with logo
    preview, On/Off toggle, Edit, Delete; "+ Add organisation"
    button at the top right.
  - **Add / Edit form** — Name, Standard (free text — e.g.
    `SZNS ISO 9001:2015`), Sort order, Logo upload (PNG/JPG/WebP/
    SVG/GIF, ≤ 5 MB), "Show on public page" checkbox. Uploaded
    logos go to `admin/uploads/orgs/`. Leaving the file empty on
    edit keeps the current logo.
  - **Delete** — confirms, removes the row, and cleans up the
    uploaded logo file if it was admin-uploaded (under
    `admin/uploads/orgs/`).
  - **Page Content tab** — all the other section copy (breadcrumb,
    intro, schemes, accreditation, portfolio, the section's own
    title/footer, docs, why-certify, process, benefits, CTA). The
    stale "logos are not edited here" note is gone — replaced with
    a pointer to the Certified Organisations tab.

### Training Calendar — new admin and pager
- Public `training-calendar.php` — 13 training cards render across
  **3 pages of 6** with `[‹] [1] [2] [3] [›]` under the list. Clicking
  a page number swaps the visible 6 cards. Calendar sidebar is
  unchanged. Clicking a training card jumps to that training's page if
  it isn't already visible (so the highlighted card stays on screen).
- Admin → `Training Calendar`:
  - **Sessions tab** — 13 trainings listed with code (coloured pill),
    title, family, intake count, Active toggle (On/Off badge), Edit,
    Delete.
  - **+ Add training** opens an empty edit form. Adding a new training
    + at least one intake (start/end date, label autofills) and saving
    appears on the public page immediately.
  - **Edit** on any row → change code/family/title, add/remove intakes
    in the repeatable sub-form. Save persists; cancel discards.
  - **Active toggle** — clicking the On/Off badge flips `is_active`
    without opening the form. Inactive trainings stop appearing on the
    public page but remain in the admin list.
  - **Delete** — confirms, then removes the session and its intakes
    (cascade via FK).
  - **Page content tab** — hero / modal / button copy editor (the
    existing 26 CMS keys, layout unchanged from before).
